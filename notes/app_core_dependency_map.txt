Note:
The C++ log_sum_exp() function is still retained for C++ routines, but R-level density/survival helper functions use matrixStats::logSumExp() for compatibility with foreach/doParallel PSOCK workers.

C++ dependency note:
The app-core C++ file no longer depends on RcppGSL, the external GNU Scientific Library, or OpenMP. Former GSL utilities were replaced with R/Rcpp-compatible alternatives, including R::digamma(), R::lgammafn(), R::runif(), R::rgamma(), and small local helper functions for squared terms, integer maximums, and double minimums. The unused OpenMP header and Rcpp OpenMP plugin were removed because the retained C++ routines do not use OpenMP-specific functions or #pragma omp directives. This makes the app easier to install across macOS, Windows, and Linux because no external GSL system library or OpenMP compiler support is required.

Parallelization note:
The app-core functions use foreach + doParallel with parallel::makeCluster(), which should be cross-platform because it uses PSOCK-style clusters rather than Unix-only forking. Custom locally sourced functions used inside foreach workers should be passed through .export rather than relying on an installed ExtendedCAPPMx package.

Parallel-worker cleanup note:
Parallel workers should be cleaned up with on.exit() immediately after cluster creation. This is important because errors or interrupted Shiny calculations can otherwise skip final stopCluster() calls and leave open connections.

Recommended pattern:

cl <- parallel::makeCluster(ncores)
doParallel::registerDoParallel(cl)

on.exit({
try(parallel::stopCluster(cl), silent = TRUE)
try(foreach::registerDoSEQ(), silent = TRUE)
}, add = TRUE)

Performance note:
The plotting, RMST, and subgroup helper functions intentionally retain foreach + doParallel parallelization to keep Shiny output generation responsive. Parallel workers are created with parallel::makeCluster(), which is more portable across Mac, Linux, and Windows than fork-based parallelization. Locally sourced helper functions are passed to workers using .export, and log-sum-exp calculations use matrixStats::logSumExp() rather than the Rcpp log_sum_exp() function to avoid external-pointer issues in PSOCK workers.

Prediction workflow note:
The Shiny app now supports prediction on a new covariate-only dataset. The prediction dataset should contain the same covariates used in model fitting, plus a prediction patient ID column. It does not need outcome, censoring, treatment, or cohort columns.

Prediction is handled by rerunning cappmx_extend_approx_fit() with the original modeling dataset as input_df and the new prediction dataset as input_df_pred:

cappmx_extend_approx_fit(
result_CAPPMx = result.CAPPMx.base,
input_df = data(),
input_specs = input.specs(),
ref_trt = input$pred_ref_treatment_selection,
input_df_pred = pred_data(),
…
)

This produces Predicted_Allocation_variables in the returned prediction result object used by the prediction tabs. Prediction outputs then call subgroup_data(…, use_pred = TRUE), which uses Predicted_Allocation_variables instead of Allocation_variables.

The Prediction Output tab supports both:

* the full uploaded prediction dataset, when no subgroup filters are applied;
* a selected prediction subgroup, when subgroup filters are enabled.

The Prediction RMST Output tab reuses RMST_result() on the prediction subgroup object returned by subgroup_data(…, use_pred = TRUE). This makes prediction RMST output structurally parallel to the existing Subgroup RMST Output.

Shiny launch note:
For local testing, the recommended launch method is RStudio’s Run App > Run in Window option. External browser mode may open multiple tabs if older Shiny sessions remain active or if the RStudio/browser launcher state is not fully cleared.

When finished, users should stop the app using the red Stop button in RStudio before launching it again.
